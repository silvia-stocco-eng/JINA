# Purpose

**Objective:**

The primary objective of this change request is to enhance the\
Notification Centre functionality by introducing a new Advanced Search\
feature while retaining the existing capabilities. By implementing an\
Advanced Search function, users will be able to easily locate relevant\
data using specific search parameters, such as time periods and\
selectable options, as outlined in the attached Excel file.

**Business Impact:**

The proposed changes will streamline the data retrieval process,\
allowing operators to quickly access the information they need.

# JPA Requirement

## Current scenario (AS-IS)

Currently, the Notification Centre provides basic functionality for\
users to receive and view notifications. However, the existing system\
lacks advanced search capabilities, making it challenging for operators\
to locate specific data efficiently. The current limitations are:

The lack of advanced search capabilities makes it difficult and\
time-consuming for operators to locate specific notifications.

- The Notification Centre page (screen 1) shows limited information,\
  without key details such as:

  - Origin BUC Series

  - BUC Number

  - Event Type

  - SED name/number à if event type is related to a Case than show only\
    the starter SED

  - Local Case ID

  - Surname and Name

- There is no way to export notification data to Excel for further\
  analysis.

- When users navigate away from the Notification Centre (e.g. by opening\
  a case) and then return, previously applied filters and search\
  criteria are lost, forcing users to reapply them.

## Future Scenario (TO-BE)

With the implementation of the new Advanced Search feature in the\
Notification Center, users will have access to a more efficient and\
user-friendly interface. This streamlined process will significantly\
reduce the time spent searching for information.

In the future scenario:

- The Notification Centre page will display additional columns,\
  including:

  - Origin BUC Series

  - BUC Number

  - Event Type

  - SED name/number à if event type is related to a Case then show only\
    the starter SED

  - Local Case ID

  - Surname and Name

In the search criteria, the start date and end date fields are mandatory\
(with the time range/volumes to be defined based on technical limits).

It will be necessary to populate at least one field among BUC Series,\
Event Type, and SED; however, it will not be mandatory to populate all\
three fields at the same time (for example, it should be possible to\
populate only Event Type and SED without necessarily having to fill in\
the BUC Series as well).

Additionally, for the BUC Series field, it will also be possible to\
populate it by entering only values such as "R_BUC" or "P_BUC", without\
the need to specify the BUC number (e.g. "R_BUC_xx" or "P_BUC_xx").

These improvements will significantly reduce the time spent searching\
for information, improve data visibility, and enhance overall usability\
of the Notification Centre.

See the Attachment "**JINA Centro Notifiche - Ricerca Avanzata**" for\
more specific information, which is available in the **Appendix 3:\
Attachments.**

### Use Case

**Use Case: Enhanced Notification Center Search**

\*\*Scenario: \*\*Users will be able to efficiently locate specific\
notifications within the Notification Centre using advanced search\
parameters while retaining their search criteria during navigation.

**Key Steps:**

- The system displays additional columns, providing key details that is\
  Origin BUC Series, BUC Number, Event Type, SED name/number (if event\
  type is related to a Case than show only the starter SED), Local Case\
  ID, Surname and Name, such as local case ID, BUC sector/type, and SED\
  name/number, enhancing data visibility.

- Users will be able to navigate away from the Notification Centre and\
  then return, retaining previously applied filters and search criteria,\
  ensuring a seamless and efficient user experience.
